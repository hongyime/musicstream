## 2026-09-18/19 — LEAK ROOT-CAUSED (glibc arenas) + fixed; SIGUSR1 + pytest-asyncio

- **The leak is glibc malloc arena bloat, NOT a Python leak.** Five tracemalloc snapshots (baseline + hourly, spanning 13h across boots) in `logs/tracemalloc.jsonl` show: RSS climbed 187 → 936 → 888 → 972 → 989 MiB (+802 MiB) while the Python-tracked top-15 allocators stayed flat at ~2.5 MiB total (top allocator `pygments/lexer.py:46` steady at 0.274 MiB the whole time). tracemalloc only sees CPython allocations; +800 MiB of untracked RSS = native memory. Confirmed via `/proc/<pid>/status`: the daemon Python process had `MALLOC_ARENA_MAX` unset, so glibc used its default of `8 × nCPU` arenas — up to 64 on this 8-vCPU host. With 11 daemon threads spawning yt-dlp / ffmpeg / librespot subprocesses continuously, freed memory gets stranded across dozens of per-arena free lists and glibc never `madvise`-returns it to the OS. Textbook Python-in-container RSS creep.
- **Fix (docker-compose.yml daemon env):** `MALLOC_ARENA_MAX=2` (force allocations onto 2 arenas; negligible throughput cost for our I/O-bound workload) + `MALLOC_TRIM_THRESHOLD_=100000` (glibc returns freed chunks >100 KB instead of hoarding). Verified active via `printenv` and `/proc/<pid>/environ`. Post-fix boot: RSS 192 MiB, 7 threads, stable. The earlier 512M→1024M limit bump (2026-09-18 pass) was a band-aid; this is the actual fix. Leave the 1 GiB limit as headroom but RSS should now plateau far below it — watch `tracemalloc.jsonl` rss_mib over the next day to confirm the plateau.
- **SIGUSR1 on-demand tracemalloc dump** (src/daemon.py): added `loop.add_signal_handler(SIGUSR1)` that spawns a dedicated daemon thread running `_tracemalloc_dump` (first tried `loop.run_in_executor` but the shared default executor is saturated by the 11 worker threads under load). Trigger: `docker kill --signal=SIGUSR1 musicstream-daemon`. **Known limitation:** testing showed the signal doesn't reach the Python process yet because `tini` (PID 1) doesn't forward SIGUSR1 through the `entrypoint.sh → gosu → uvicorn` exec chain. Fixed by adding `-g` to the `tini` ENTRYPOINT in Dockerfile.daemon (forwards to the whole process group) — **but this needs an image REBUILD to take effect.** The hourly-cron dump path works fine regardless (it's what produced the diagnostic snapshots), so SIGUSR1 is a convenience, not load-bearing.
- **pytest-asyncio==0.26.0** added to requirements.txt (single source of truth — Dockerfile does `pip install -r requirements.txt`). Fixes the 7 failing tests (3 in test_daemon_robustness.py `@pytest.mark.asyncio`, 4 in test_integration_endpoints.py). **Also needs the rebuild** to bake into the image.
